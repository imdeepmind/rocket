# Introduction

<p align="center">
  <img src="img/logo.png" alt="ROSS API Framework Logo" width="200" />
</p>

ROSS is an open-source, configuration-driven REST API framework based on Fastify. Instead of writing repetitive boilerplate for models, routes, validation, and docs, you declare your application in a single structured configuration and ROSS handles database schema management, CRUD/search/aggregate endpoints, request validation, authentication, RBAC, caching, outbound webhooks, and interactive OpenAPI/Swagger documentation automatically.

## Two Ways to Use ROSS

You can run ROSS as a standalone CLI over a JSON file or use it programmatically in your Node.js/TypeScript code.

### CLI (`ross`)

Point the CLI at a `ross.json` configuration file and let ROSS manage the full server lifecycle—no application code required.

- **Zero boilerplate**: Define models, auth, caching, and custom SQL/function endpoints in JSON and boot immediately with `ross dev` or `ross start`.
- **Built-in tooling**: Validate configs (`ross config validate`), inspect resolved defaults with secrets redacted (`ross config show`), and run schema/custom migrations (`ross migrate`).
- **Best for**: Rapid prototyping, standard CRUD/data APIs, and teams that want a declarative backend without maintaining server glue code.

See the [Getting Started](./get-started.md) guide and [CLI Reference](./cli.md).

### Programmatic (`@imdeepmind/ross`)

Import `createServer`, `defineConfig`, and `migrateDatabase` directly into your Node.js or TypeScript codebase while keeping full control of the Fastify instance.

- **Type-safe configuration**: Author configs in TypeScript using `AppConfigInput` and split large setups across multiple modules.
- **Full Fastify control**: Attach custom hooks, plugins, or routes, and decide when to call `app.listen()` and `app.close()`.
- **Test-friendly**: Exercise routes in-process with `app.inject()` without binding a network port.
- **Best for**: Existing Fastify services, custom middleware/business logic, and TypeScript-first projects.

See [Programmatic Usage](./programmatic.md).

## Barebone Example

The smallest configuration that boots a working API needs only `application.name` and `data.models`:

```json title="ross.json"
{
  "application": { "name": "Barebone API" },
  "data": {
    "models": {
      "notes": {
        "fields": {
          "id": { "type": "integer", "primaryKey": true, "autoIncrement": true },
          "title": { "type": "string", "nullable": false },
          "body": { "type": "text", "nullable": true }
        }
      }
    }
  }
}
```

Start the development server:

```bash
ross dev -c ross.json
```

With that single model, ROSS sets up a local SQLite database (`./database.db`), mounts REST endpoints under `/api/v1/notes` (`POST`, `GET`, search, `PATCH`, `PUT`, `DELETE`), and serves interactive Swagger UI at `/docs`.
